## Principle Summary

W3C TAG Design Principle §1.5 ("Use identity appropriately in context") directs spec authors to give end users transparency and control over how identifying information is presented across different web contexts. Because identifiers and attached behavioral or form-submitted data carry cross-cutting privacy and tracking risks, web APIs must be designed around user intent, collect the minimum data necessary, and default to short-lived, temporary, context-scoped identifiers rather than persistent global identifiers whenever possible.

In practice, this principle shapes browser privacy boundaries across APIs like WebAuthn (relying-party-scoped credentials rather than global device IDs), FedCM (mediated federated sign-in without third-party cookie tracking), `MediaDevices.enumerateDevices()` (origin-scoped, resettable `deviceId` values gated on permissions), and Web Bluetooth / WebUSB device permissions. It exists to protect end users from cross-site correlation and over-collection of personal data by websites.

## Fit for Coding Agents

This principle is neutral with respect to AI coding agents because it governs the privacy boundary between the browser/end-user and the website, rather than the developer ergonomics (DX) of authoring or maintaining code. Whether a relying party's JavaScript is written by a human engineer or generated by an LLM coding agent, the browser must enforce data minimization and ephemeral, origin-scoped identifiers so the site cannot track users across contexts.

From a coding-agent behavior perspective, there is a minor secondary interaction: LLM coding agents optimize heavily for making requested functionality work as quickly as possible and rarely perform unsolicited privacy threat modeling or data minimization on their own. If a platform API exposes a convenient persistent identifier alongside an ephemeral one, or returns an overly broad user profile object by default, an agent will readily bind to and persist whatever fields appear in its training distribution or type definitions. Enforcing data minimization and short-lived identifiers at the Web API boundary therefore remains a critical safety guardrail in an agent-authored web—and occasionally creates minor test/debugging friction when agents assume identifiers (such as media `deviceId` or credential handles) are globally static across origins or sessions—but the principle itself neither targets nor needs to change for coding-agent ergonomics.

## Value as a Slide Example

This principle is not useful as a slide example (`neither`, 1/5) for a TPAC session on how coding agents redefine Developer Experience (DX). Because §1.5 is fundamentally about end-user privacy, anti-tracking, and user-mediated identity disclosure (as seen in WebAuthn relying-party-scoped credentials, FedCM, or origin-scoped `MediaDevices.enumerateDevices()` IDs), featuring it on a slide would conflate end-user privacy protections with developer/agent API ergonomics—or distract the audience into a tangential discussion about autonomous browser-use agents acting on a user's behalf, rather than coding agents authoring web applications.

At most, it belongs in a brief blanket acknowledgment that end-user security and privacy principles (such as data minimization and context-scoped identifiers at the API boundary) remain invariant and serve as essential guardrails when AI coding agents write application code without doing their own privacy threat modeling.
