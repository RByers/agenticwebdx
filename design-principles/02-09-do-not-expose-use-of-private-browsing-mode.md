## Principle Summary

W3C TAG Design Principle §2.9 ("Don’t reveal that private browsing mode is engaged") states that web specifications and browser features must not provide websites with any direct or indirect mechanism to detect whether a user is in private browsing (incognito) mode. Because users often rely on private browsing mode for personal safety—protecting themselves from abusive partners, employers, parents, or state actors—the mere fact that someone is using private mode is sensitive information that must not be leaked to origins.

To protect users without leaking this state, features that restrict behavior in private browsing mode must do so in a way that is indistinguishable from normal browsing outcomes. For example, the Payment Request API permits User Agents to automatically abort payment requests in private browsing mode (preventing accidental disclosure of billing or shipping addresses) using the exact same rejection signal as a normal user cancellation.

## Fit for Coding Agents

This principle is neutral with respect to AI coding agents because it establishes a non-negotiable end-user privacy and personal-safety boundary rather than a developer experience or API ergonomics trade-off. The threat model—websites attempting to detect, track, or gate content against users in private browsing mode—depends on the incentives of the origin operator, not on whether the site's code was written by a human developer or generated by an LLM.

If anything, the widespread use of AI coding agents makes enforcing this principle at the specification and browser level even more critical. LLM training corpora contain years of Stack Overflow posts and fingerprinting libraries that attempt to detect incognito mode through historical browser quirks (such as probing `webkitRequestFileSystem`, catching `localStorage` quota exceptions in older Safari versions, or inspecting `navigator.storage.estimate()` heuristics). When prompted to "detect incognito mode to enforce a metered paywall," a coding agent will effortlessly synthesize these side-channel probes from its training priors. Upholding §2.9 ensures that such agent-generated detection scripts fail to distinguish private mode.

For benign application code, the principle has two minor, offsetting implications for coding agents. On the positive side, because modern browsers expose uniform, working APIs in private browsing mode (e.g., backing `indexedDB`, `localStorage`, and `CacheStorage` with ephemeral in-memory storage instead of disabling them or throwing mode-specific errors), coding agents do not need to litter generated code with defensive branches for private mode. On the flip side, because privacy-preserving aborts (such as `PaymentRequest.show()` rejecting as if the user cancelled) intentionally conceal the underlying cause from page script, an agent diagnosing errors strictly via in-page telemetry cannot tell whether a user cancelled or was in private browsing mode—an intentional and unavoidable consequence of protecting the user.

## Value as a Slide Example

This principle is not useful as an individual slide example (`neither`, strength 1/5) for a TPAC session on how web standards should adapt to AI coding agents. It is purely an end-user privacy and safety invariant, and there is no plausible argument that web standards should weaken private browsing protections for the sake of agent ergonomics or observability.

In the context of the presentation, its only value is as part of the aggregate baseline tally of W3C TAG principles that protect end users from origins (security, privacy, and hardware/personal safety) and therefore remain completely unchanged by the shift from human-authored code to agent-authored code.
